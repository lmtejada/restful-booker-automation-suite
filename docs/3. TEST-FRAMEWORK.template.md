## 3. Path aliases

| Alias          | Resolves to         |
| -------------- | ------------------- |
| `@fixtures/*`  | `./src/fixtures/*`  |
| `@enums/*`     | `./src/enums/*`     |
| `@test-data/*` | `./src/test-data/*` |
| `@utils/*`     | `./src/utils/*`     |
| `@pages/*`     | `./src/pages/*`     |
| `@app-types/*` | `./src/types/*`     |

**Why:** avoids relative-path hell (`../../../src/fixtures/app`) across a deep `tests/`/`src/` split — every import says what it's getting by intent, not by its accidental file location.

**Gotcha:** don't name an alias `@types/*` — TypeScript reserves that name for ambient `@types/*` declaration packages, and aliasing over it breaks resolution outright. Use `@app-types/*` instead.

**No extra runtime loader needed:** Playwright's own TS transform reads these straight from `tsconfig.json`'s `paths` — no `tsconfig-paths` or `tsx` loader required. ESLint is the only place needing `eslint-import-resolver-typescript` configured to resolve the same aliases.

## 7. Lint rules & rationale

_Not an exhaustive list of every lint rule — just the ones worth explaining because the reason isn't obvious from the rule name alone._

| Rule                                      | Why                                                                                               |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `playwright/no-wait-for-timeout`          | No hard waits — forces explicit/web-first waiting instead of sleeping and hoping.                 |
| `playwright/prefer-web-first-assertions`  | Auto-retrying assertions over manual, non-retrying reads.                                         |
| `playwright/no-raw-locators`              | Semantic locators (`getByRole`, `getByTestId`) over brittle CSS/XPath.                            |
| `import-x/order`                          | Enforced import grouping/alphabetization — see §3 for the alias-specific ordering.                |
| `@typescript-eslint/no-floating-promises` | Every async page-object call must be awaited — a common source of Playwright flakiness otherwise. |

## 8. Test data strategy

- **`test-data/static/`** — fixed, deterministic fixtures: data that represents "this is a fact about the real app/catalog."
- **`test-data/factories/`** — functions that generate data with overrides, for deliberate edge-case variations.

**Rule of thumb:** if the data is a fixed fact, it belongs in `static/`. If it's "a valid baseline with deliberate variations," it belongs in `factories/`.

### 10.2 Known-bug capture pattern (`test.skip` convention)

**Rule:** when testing surfaces a genuine defect, don't just note it — write the test asserting _correct_ behavior, skip it with a reason pointing at the bug ID, and log a matching defect-log row.

**Why:** keeps bugs as executable documentation instead of prose that drifts out of sync with reality.

### 10.3 Commit message & branch name conventions

**Rule — commits:** `commitlint.config.js` (Conventional Commits) enforced via a `commit-msg` Husky hook.

**Rule — branches:** a `pre-push` hook requires a `feat/`, `fix/`, `release/`, or `epic/` prefix (`main` exempt); back this up with a GitHub repository ruleset, since the local hook alone can be bypassed with `--no-verify`.

**Why:** if PRs merge with regular merges (not squash), every commit message lands in permanent history, so message quality is worth enforcing at commit time. Branch names get a server-side backstop because GitHub can enforce a branch-name pattern on creation; there's no equivalent GitHub-native way to enforce commit-message format on a regular merge.
